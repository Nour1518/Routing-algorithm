# GRAPH ROUTING API MANUAL

Application:
GraphApi.py

Framework:
Flask

Default server:
http://127.0.0.1:5000

============================================================

1. START THE API
   ============================================================

Install Flask:

```
pip install flask
```

Start the server:

```
python GraphApi.py
```

The API will listen on:

```
http://127.0.0.1:5000
```

If the server is running on another machine on the network,
use:

```
http://<SERVER-IP>:5000
```

The application uses:

```
host = 0.0.0.0
port = 5000
```

============================================================
2. API OVERVIEW
===============

Available endpoints:

```
GET     /
GET     /graphs

POST    /graphs/generate
POST    /graphs/load

GET     /graphs/<graph_id>

POST    /graphs/<graph_id>/route
POST    /graphs/<graph_id>/ch
POST    /graphs/<graph_id>/save

DELETE  /graphs/<graph_id>
```

The API keeps loaded/generated graphs in memory.

Each graph receives a unique graph ID.

Example:

```
8c2f5d7e4a...
```

The graph ID is used for subsequent operations.

============================================================
5. GENERATE A GRAPH
===================

Endpoint:

```
POST /graphs/generate
```

Content-Type:

```
application/json
```

The graph type is specified using:

```
"type"
```

Supported types:

```
generic
random
geographical
grid
```

---

## 5.1 GENERIC GRAPH

Request:

```
{
    "type": "generic",
    "nodes": 100,
    "directed": false
}
```

Example:

```
curl -X POST http://127.0.0.1:5000/graphs/generate \
  -H "Content-Type: application/json" \
  -d "{\"type\":\"generic\",\"nodes\":100}"
```

A generic graph creates the requested nodes.

No edges are automatically created.

---

## 5.2 RANDOM GRAPH

Request:

```
{
    "type": "random",
    "nodes": 100,
    "probability": 0.05,
    "min_weight": 1,
    "max_weight": 100,
    "directed": false
}
```

Parameters:

```
nodes
    Number of nodes.

probability
    Probability of creating an edge.

min_weight
    Minimum edge weight.

max_weight
    Maximum edge weight.

directed
    true or false.
```

Example:

```
curl -X POST http://127.0.0.1:5000/graphs/generate \
  -H "Content-Type: application/json" \
  -d "{\"type\":\"random\",\"nodes\":100,\"probability\":0.05,\"min_weight\":1,\"max_weight\":100}"
```

---

## 5.3 GEOGRAPHICAL GRAPH

Request:

```
{
    "type": "geographical",
    "nodes": 500,
    "size": 1000,
    "min_dist": 10,
    "radius": 150,
    "max_degree": 4,
    "directed": false
}
```

Parameters:

```
nodes
    Number of geographical nodes.

size
    Size of the geographical area.

min_dist
    Minimum distance between generated nodes.

radius
    Maximum distance for additional local connections.

max_degree
    Maximum node degree.

directed
    true or false.
```

Example:

```
curl -X POST http://127.0.0.1:5000/graphs/generate \
  -H "Content-Type: application/json" \
  -d "{\"type\":\"geographical\",\"nodes\":500,\"size\":1000,\"min_dist\":10,\"radius\":150,\"max_degree\":4}"
```

The geographical generator:

```
1. Generates node coordinates.
2. Enforces minimum distance.
3. Builds an MST.
4. Guarantees connectivity.
5. Adds local geographical edges.
6. Respects maximum degree.
```

---

## 5.4 GRID GRAPH

Request:

```
{
    "type": "grid",
    "rows": 20,
    "cols": 20,
    "weight": 1,
    "diagonal": false,
    "directed": false
}
```

Parameters:

```
rows
    Number of grid rows.

cols
    Number of grid columns.

weight
    Edge weight.

diagonal
    Enable diagonal connections.

directed
    true or false.
```

Example:

```
curl -X POST http://127.0.0.1:5000/graphs/generate \
  -H "Content-Type: application/json" \
  -d "{\"type\":\"grid\",\"rows\":20,\"cols\":20,\"weight\":1,\"diagonal\":true}"
```

============================================================
6. DIRECTED GRAPH GENERATION
============================

Use:

```
"directed": true
```

Example:

```
{
    "type": "random",
    "nodes": 100,
    "probability": 0.05,
    "directed": true
}
```

For a directed edge:

```
A -> B
```

the reverse:

```
B -> A
```

is NOT automatically available.

For an undirected graph:

```
"directed": false
```

the graph internally stores both directions.

7. BUILD CH DURING GENERATION
=============================

```
{
    "type": "geographical",
    "nodes": 500,
    "size": 1000,
    "min_dist": 10,
    "radius": 150,
    "max_degree": 4,
    "build_ch": true
}
```

Example:

```
curl -X POST http://127.0.0.1:5000/graphs/generate \
  -H "Content-Type: application/json" \
  -d "{\"type\":\"geographical\",\"nodes\":500,\"build_ch\":true}"
```

The response includes:

```
"ch": {
    "time_seconds": ...,
    "statistics": ...,
    "ch_ready": true
}
```

## 12.2 A*

Request:

```
{
    "start": 0,
    "goal": 400,
    "algorithm": "a_star"
}
```

The heuristic is automatically selected according to
graph type.

Geographical / road:

```
Euclidean heuristic.
```

Grid:

```
Manhattan-distance heuristic.
```

Generic / random:

```
Zero heuristic.
```

============================================================
13. ROUTING RESPONSE
====================

A successful routing request returns:

```
{
    "success": true,
    "graph_id": "8c2f5d7e4a...",
    "query": {
        "start": 0,
        "goal": 400,
        "algorithm": "a_star"
    },
    "result": {
        "found": true,
        "cost": 532.41,
        "time_seconds": 0.00123,
        "path": [
            0,
            12,
            45,
            87,
            400
        ],
        "path_nodes": 5,
        "path_edges": 4,
        "path_length": 532.41
    },
    "trace": null
}
```

Important result fields:

```
found
    Whether a route was found.

cost
    Cost returned by the routing algorithm.

time_seconds
    Algorithm execution time.

path
    Ordered list of node IDs.

path_nodes
    Number of nodes in the route.

path_edges
    Number of edges in the route.

path_length
    Independently calculated path length when possible.
```

14. SEARCH TRACE
================

Request:

```
{
    "start": 0,
    "goal": 400,
    "algorithm": "a_star",
    "trace": true
}
```

Example:

```
curl -X POST http://127.0.0.1:5000/graphs/8c2f5d7e4a.../route \
  -H "Content-Type: application/json" \
  -d "{\"start\":0,\"goal\":400,\"algorithm\":\"a_star\",\"trace\":true}"
```

the response can contain:

```
"trace": {
    "expansion_count": ...,
    "edge_check_count": ...,
    "meeting_node": ...
}
```

The exact trace contents depend on the implementation of
the Graph visualization methods.

19. PYTHON CLIENT EXAMPLE
=========================

The API can also be used from Python.

Install requests:

```
pip install requests
```

Generate a graph:

```
import requests

response = requests.post(
    "http://127.0.0.1:5000/graphs/generate",
    json={
        "type": "geographical",
        "nodes": 500,
        "size": 1000,
        "min_dist": 10,
        "radius": 150,
        "max_degree": 4
    }
)

data = response.json()

graph_id = data["id"]

print(graph_id)
```

Run A*:

```
response = requests.post(
    f"http://127.0.0.1:5000/graphs/{graph_id}/route",
    json={
        "start": 0,
        "goal": 400,
        "algorithm": "a_star"
    }
)

print(response.json())
```

21. ERROR RESPONSES
===================

Errors are returned as JSON.

Example:

```
{
    "success": false,
    "error": "Graph not found."
}
```

Common errors:

```
Graph not found.
    The supplied graph ID does not exist.

Missing 'start'.
    Start node was not provided.

Missing 'goal'.
    Goal node was not provided.

Unknown algorithm.
    The requested algorithm is not supported.

Start node X does not exist.
    The requested start node is not in the graph.

Goal node X does not exist.
    The requested goal node is not in the graph.

CH is not ready.
    CH was requested without building the hierarchy.
```

============================================================
22. IMPORTANT STORAGE BEHAVIOR
==============================

Graphs are stored in memory:

```
GRAPHS = {}
```

Therefore:

```
API starts
    |
    +-- Graph generated
    |
    +-- Graph stored in RAM
    |
    +-- Queries use the same Graph object
    |
    +-- API stops
          |
          +-- Graphs are lost
```

Restarting GraphApi.py removes all graphs from memory.

Graphs must therefore be saved to disk if they need to
survive a server restart.

============================================================
24. CURRENT API LIMITATION
==========================

The current API provides graph statistics and routing paths,
but it does not yet provide a dedicated endpoint returning
the complete graph topology.

For a graphical visualization interface, an additional
endpoint should eventually provide:

```
- Node IDs
- Node coordinates
- Node metadata
- Edge source
- Edge target
- Edge weight
- Directed/undirected information
```

For example:

```
GET /graphs/<graph_id>/data
```

This would allow a frontend to render the graph without
direct access to the Python Graph object.
